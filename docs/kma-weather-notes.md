# 기상청 날씨 API 노트 (김포시 마산동)

조사/시험일: 2026-10-18. 인증키는 `.env.local`의 `KMA_SERVICE_KEY` (GitHub에 올라가지 않음). 키 값은 문서/로그에 적지 않는다.

## 위치
- 위도 37.640, 경도 126.643 (김포시 마산동), 기상청 격자 **nx=54, ny=128** (Lambert 변환 공식으로 계산).

## 사용할 API (모두 확인됨, HTTP 200 / NORMAL_SERVICE)
기본 주소: `https://apis.data.go.kr/1360000/VilageFcstInfoService_2.0/`
공통 파라미터: `serviceKey`(URL 인코딩 필요, curl은 `--data-urlencode`), `dataType=JSON`, `nx=54`, `ny=128`, `base_date`, `base_time`.

| API | 용도 | 발표 기준 | 응답 크기 |
|---|---|---|---|
| `getUltraSrtNcst` 초단기실황 | **현재 기온 `T1H`**, 강수형태 `PTY`, 1시간 강수량 `RN1` | 매시 정각, **40분 이후 제공** (그 전이면 한 시간 전 기준) | 작음 |
| `getUltraSrtFcst` 초단기예보 | 6시간 `SKY`, `PTY`, `T1H`, `POP`, `RN1`, `LGT` | 매시 30분 발표, **45분 이후 제공**, `base_time=HH30` | 약 9KB (66행) |
| `getVilageFcst` 단기예보 | 며칠 `SKY`, `PTY`, `POP`, `TMP`, `PCP`, `TMN/TMX` | 02,05,08,11,14,17,20,23시 발표, **+10분 이후 제공** | 290행 요청에 약 39KB |

## 값의 의미
- `SKY`: 1 맑음, 3 구름많음, 4 흐림 (2는 쓰이지 않음)
- `PTY`: 0 없음, 1 비, 2 비/눈, 3 눈, 4 소나기 (초단기에서는 5 빗방울, 6 빗방울눈날림, 7 눈날림도 있음)
- `POP`: 강수확률(%). **초단기예보 응답에도 `POP`이 들어 있다** (시험 결과 확인).
- `LGT`: 낙뢰 (0 없음). 번개 아이콘에 쓸 수 있다.
- 안개 항목은 없다. 안개 아이콘은 기상청 데이터로는 판정할 수 없다.
- 실황에는 `SKY`가 없다. 하늘 상태는 가장 가까운 예보 시각의 `SKY`를 쓴다.

## 표시 규칙 초안
- 아이콘: 현재 `PTY`가 0이 아니면 강수 아이콘(비/눈/비눈/소나기), 0이면 `SKY`(낮 맑음/구름많음/흐림, 밤은 달). `LGT`가 있으면 천둥.
- "A뒤B": 앞으로 몇 시간의 `SKY`/`PTY` 흐름을 보고 판정 (맑은뒤흐림, 비온뒤갬 등).
- 기온은 `T1H`(실황), 강수확률은 가장 가까운 예보 시각의 `POP`.

## 주의
- 발표 시각 전에 호출하면 데이터가 없다(`resultCode` 03 등). 기준 시각 계산이 중요하다.
- 호출은 실황 10~30분, 예보 1~3시간 간격이면 충분하다. 일일 호출 한도는 확인하지 못했다.
- 키는 허브/시계 어디에 두든 코드에 직접 쓰지 않는다.

## 구현: 시계 스크립트 (2026-10-18)
허브 드라이버에서 시도했으나 **허브의 드라이버 실행 환경은 외부 주소(DNS)를 찾지 못해** 기상청뿐 아니라 다른 사이트도 접속되지 않았다 (HTTP/HTTPS 모두 실패, IP 직접 접속은 시험하지 않음). 그래서 시계 안의 Berry 스크립트가 직접 기상청 HTTPS를 호출한다.

- 스크립트: `scripts/weather.be` (앱 이름 `weather`). 올리기: `scripts/deploy-weather.sh`.
- 인증키: `.env.local`의 `KMA_SERVICE_KEY`를 읽어 시계 앱 설정값(`kma_key`)으로 넣는다. 스크립트 소스에는 키가 없다. 단, 시계의 `GET /api/v1/apps/weather/config`로 같은 Wi-Fi에서 키를 읽을 수 있다 (인증 미사용).
- 갱신: 매시 50분에 한 번 (실황 1회 + 초단기예보 4회). 실패하면 5분 뒤 재시도, 3시간 넘게 갱신 못 하면 화면에서 뺀다.
- 응답이 8KB를 넘어(초단기예보 약 9KB, `POP`가 맨 끝) `http.get`의 `find`/`keep`으로 항목별(`SKY`, `PTY`, `POP`, `LGT`)로 필요한 부분만 받는다. 항목은 6시간치 6행씩 순서대로 온다.
- 표시: `[날씨 아이콘 0-7] 기온(x=11~) 우산(3칸) 확률(오른쪽 끝)`. `°`와 `%`는 공간 때문에 뺐다. 확률 100%는 99로 표시. 기온 -10 이하는 한 칸 왼쪽으로.
- 표시 시간: 시계 전체 앱 표시 시간을 10초(`appDurationMs`)로 두고 날씨 스크립트만 `duration()`으로 5초. 태양광 10초, 날씨 5초가 번갈아 나오는 것을 확인했다.
- 아이콘(`assets/weather/*.gif`, 14종): sunny, clear_night, partly_day, partly_night, cloudy, clear_to_cloudy(맑은뒤흐림), rain_to_clear(비온뒤갬), drizzle, rain, shower, thunder, snow, sleet, fog. 안개(fog)는 기상청 데이터에 없어 쓰이지 않는다.
- 아이콘 규칙: 낙뢰 > 강수형태(비/소나기/빗방울/진눈깨비/눈, 비온뒤갬) > 하늘상태(맑음/구름많음/흐림, 맑은뒤흐림). 낮/밤은 김포 일출/일몰 근사식.
- 확인: 첫 갱신 `partly_night 17도 강수확률 20%`가 기상청 응답과 일치.

## 알아둘 점
- 시계가 재부팅되면 스크립트는 유지되지만(앱 설정도 유지) 다시 받아올 때까지 화면에서 빠진다.
- 키를 바꾸면 `scripts/deploy-weather.sh`를 다시 실행한다.

## 표시 세부 (2026-10-18)
- 기온 색은 주황(`0xFFA500`), 확률은 파랑, 우산은 파랑.
- 영하 표시: 마이너스를 글자(3칸+간격) 대신 **2칸짜리 선**(행 3)으로 직접 그린다. 숫자 2자리일 때 선 x=8~9, 간격 10, 숫자 11~17, 한 칸(18) 비우고 우산 19~23, 확률 25~31. `-23도, 강수확률 89%`로 실제 화면 확인: 우산과 붙지 않는다. 한 자리 영하(-5)는 선 x=9~10, 숫자 12~.
- 알려진 점: 마이너스 선(x=8)이 아이콘 오른쪽 끝(x=7)에 붙는 모양이 있다 (구름 계열 아이콘은 7열이 채워져 있음).
- 시험 방법: 임시 앱(`weather_test`)에 시험 값을 넣어 올리고 `GET /api/v1/display/screen`으로 픽셀을 읽는다. 끝나면 `DELETE /api/v1/apps/weather_test`.
- Berry 주의: `return` 다음 줄에 식이 오면 그 식을 반환값으로 읽는다 (본 스크립트는 `return` 뒤에 항상 `end`).
- 시계에 앱을 연달아 설치하면 여유 메모리가 줄어 첫 요청이 `status=0`으로 실패할 수 있다. 5분 뒤 자동 재시도로 복구된다.

## 배치 조정 (2026-10-18, 우산 3칸)
- 우산을 5칸에서 **3칸 폭**으로 줄이고(`.X.` / `XXX` / `.X.` / `.X.` / `XX.`), 기온을 2칸 오른쪽(x=11~)으로 당겼다. 영하의 마이너스(2칸 선)가 아이콘에서 2칸 떨어진다.
- 확인한 화면(실제 compute 로직에 시험 값 주입): `-23도 89%` 선 10-11, 숫자 13-19, 우산 21-23, 확률 25-31. `15도 20%` 숫자 11-17. `-5도 5%` 선 11-12, 숫자 14-16.
- 위의 "마이너스(x=8)가 아이콘에 붙는다"는 알려진 점은 이 조정으로 해결됐다.
